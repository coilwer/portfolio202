Case study

Task List

Plain JavaScript · localStorage · GitHub Pages · Oleksandr Plotnikov

Idea

My first portfolio project: a small task list, built to practise core JavaScript without a framework.

What it does

You can add tasks, mark them as done, delete them, filter by All, Active or Done, and clear completed tasks. Tasks stay in the browser after a reload thanks to localStorage.

Key decisions

I used plain HTML, CSS and JavaScript, with no framework, to learn how the DOM, events and state work. Tasks live in one array and the list is redrawn from it after every change. User text is inserted with textContent, so it is never parsed as HTML. Checkboxes have labels, filter buttons use aria-pressed and focus states are visible, so the app works with a keyboard. Storage calls are wrapped in try/catch, so the app keeps working if the browser blocks localStorage.

Result

A working app, published on GitHub Pages, with the source code on GitHub. The next step is a second project in React, to compare both approaches.

Source code of this site

Чистый JavaScript · localStorage · GitHub Pages · Oleksandr Plotnikov

Идея

Мой первый проект для портфолио: небольшой список задач, сделанный, чтобы отработать основы JavaScript без фреймворка.

Что он умеет

Можно добавлять задачи, отмечать их выполненными, удалять, фильтровать по «All», «Active» и «Done» и очищать выполненные. Благодаря localStorage задачи остаются в браузере после перезагрузки.

Ключевые решения

Я взял чистые HTML, CSS и JavaScript без фреймворка, чтобы разобраться, как работают DOM, события и состояние. Задачи хранятся в одном массиве, и после каждого изменения список перерисовывается из него. Текст пользователя вставляется через textContent, поэтому никогда не разбирается как HTML. У чекбоксов есть подписи, у кнопок фильтра есть aria-pressed, а фокус виден, так что приложением можно пользоваться с клавиатуры. Обращения к хранилищу обёрнуты в try/catch, поэтому приложение работает, даже если браузер блокирует localStorage.

Результат

Рабочее приложение, опубликованное на GitHub Pages, с исходным кодом на GitHub. Следующий шаг: второй проект на React, чтобы сравнить два подхода.
